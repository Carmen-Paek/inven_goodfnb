# 소비기한 재고관리 (A완제품창고)

부모코드(상품코드)와 자식코드(`상품코드-소비기한`, 예: `AG00229-20270401`) 단위로 재고를 관리하는 웹앱입니다.
출고 엑셀을 올리면 소비기한·코드·수량을 읽어 해당 자식코드에서 차감합니다.

- **재고현황**: 부모코드별 합계와 자식코드별 수량, 소비기한 D-day, 경과/임박/주의 표시, 엑셀 다운로드
- **엑셀 업로드**: 출고(차감) / 입고(가산) / 실사(수량 맞춤) → 검증 미리보기 → 반영
- **입출고 이력**: 업로드 단위 기록, 상세 원장, **되돌리기**
- **상품 마스터**: 부모코드 추가

---

## 1. 바로 써보기 (설정 없이)

`index.html`을 브라우저로 열면 **로컬 데모 모드**로 실행됩니다.
`발주수량관리.xlsx`의 9/7 실사재고와 9/10 입고예정이 미리 들어가 있습니다.
데모 모드의 데이터는 그 브라우저에만 저장됩니다.

## 2. GitHub에 올려 온라인으로 열기 (GitHub Pages)

1. GitHub에서 **New repository**를 만듭니다 (예: `inventory`).
2. **Add file → Upload files**에서 이 폴더 안의 파일과 폴더를 전부 끌어다 놓고 **Commit**합니다.
3. **Settings → Pages**로 이동해 Source를 `Deploy from a branch`, Branch를 `main` / `/(root)`로 지정하고 **Save**합니다.
4. 1~2분 뒤 `https://<아이디>.github.io/inventory/` 주소로 접속할 수 있습니다.

> 이 단계까지는 데모 모드입니다. 여러 명이 같은 재고를 보려면 3번을 진행하세요.
> 저장소가 Public이면 코드는 공개되지만, 재고 데이터는 Supabase에 있고 로그인한 사람만 볼 수 있습니다.

## 3. 실제 운영 DB 연결 (Supabase, 무료 플랜 가능)

1. https://supabase.com 에서 **New project**를 만듭니다. Region은 `Northeast Asia (Seoul)`을 권장합니다.
2. **SQL Editor**에서 아래 두 파일을 순서대로 붙여넣고 **Run**합니다.
   - `supabase/schema.sql`: 테이블, 차감 함수, 보안 설정
   - `supabase/seed.sql`: 초기 재고 (9개 상품, 42개 자식코드). **한 번만** 실행하세요.
3. **Authentication → Users → Add user**에서 사용할 계정(이메일, 비밀번호)을 만듭니다.
4. **Authentication → Sign In / Providers → Email**에서 `Allow new users to sign up`을 **끕니다**. 외부인이 가입하지 못하게 하기 위해서입니다.
5. **Project Settings → API**에서 `Project URL`과 `anon public` 키를 복사해 `config.js`에 넣습니다.
   ```js
   SUPABASE_URL: "https://xxxx.supabase.co",
   SUPABASE_ANON_KEY: "eyJhbGciOi...",
   ```
6. GitHub에서 `config.js`를 수정(연필 아이콘)하고 Commit하면 1~2분 뒤 사이트가 로그인 화면으로 바뀝니다.

## 4. 엑셀 업로드 규칙

| 열 | 인식되는 이름 (예시) | 비고 |
|---|---|---|
| 부모코드 | 상품코드, 품목코드, ERP품목코드, 부모코드 | 필수 (자식코드 열이 있으면 생략 가능) |
| 소비기한 | 소비기한, 유통기한 | `2027-04-01`, `2027.04.01`, `20270401`, 엑셀 날짜 모두 가능 |
| 수량 | 출고수량, 입고수량, 실사수량, 수량 | 박스 단위 |
| 자식코드 | 자식코드, 로트코드 | `AG00229-20270401` 형식이면 코드와 소비기한을 자동 분리 |
| 참조 | 주문번호, 출고처, 거래처, 비고 | 선택 |

- 제목 행이나 빈 행이 위에 있어도 헤더 행을 자동으로 찾습니다. 자동 인식이 틀리면 화면의 **열 매칭**에서 바꾸면 됩니다.
- 코드가 비어 있는 소계/합계 행은 자동으로 건너뜁니다.
- **출고에서 소비기한을 비우면** 소비기한이 빠른 순서(FEFO)로 자동 배분합니다. 이미 경과한 로트는 제외합니다.
- 오류(없는 자식코드, 재고 부족, 미등록 코드)가 하나라도 있으면 기본적으로 반영되지 않습니다. `오류 행은 제외하고 반영`을 체크하면 정상 행만 반영합니다.
- 같은 파일을 두 번 올리면 차단됩니다. 잘못 올린 파일은 **입출고 이력 → 되돌리기**로 취소합니다.

## 5. 초기 데이터 관련 참고

- 기준 시점은 **9/7 실사재고 + 9/10 입고예정**입니다. 원본 시트는 9/10 이후 출고 열의 수식이 `#NAME?` 오류여서 잔여재고를 확정할 수 없었습니다.
  → 현재 재고에 맞추려면 **실사 업로드**로 현재 수량을 한 번 올리거나, 9/10 이후 출고 파일을 순서대로 올리세요.
- 배도라지 20 `2027-03-30`은 시트에 두 행(7 + 818)으로 나뉘어 있어 하나의 자식코드(825)로 합쳤습니다.
- 보리보리 20 `2026-09-23`(281박스, 시트 메모 "폐기")은 **경과**로 표시됩니다. 폐기 처리하려면 재고현황에서 **수정 → 0**을 입력하세요.

## 폴더 구조

```
index.html        화면
app.js            동작 (엑셀 해석, 검증, 차감, 데모/Supabase 데이터 계층)
styles.css        디자인
config.js         Supabase 접속 정보, 임박 기준일(D-30/D-90)
data/seed.js      데모 모드 초기 데이터
supabase/
  schema.sql      DB 테이블, apply_upload / revert_upload / adjust_lot 함수, 보안
  seed.sql        운영 DB 초기 데이터
scripts/
  build_seed.py   초기 데이터 수정 시 seed.js / seed.sql 재생성
```

## 데이터 구조

```
products (부모코드)  1 ─── N  lots (자식코드 = 부모코드-소비기한, 현재고)
                                  │
uploads (엑셀 1건) 1 ─── N  movements (입출고 원장: +입고 / -출고 / 조정 / 취소)
```

재고 수량은 `lots.qty`에 있고, 모든 변동은 `movements`에 남습니다.
차감은 DB 함수(`apply_upload`) 안에서 처리됩니다. 한 행이라도 실패하면 파일 전체가 취소되므로 재고가 반만 차감되는 일은 없습니다.
